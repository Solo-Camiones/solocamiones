## Objetivo

Desde el listado, el operador identifica de un vistazo qué es la pieza, dónde está, si se puede vender, si pertenece a un ensamblaje y si hay una restricción. INV-003 sigue separado: no hay un estado fusionado.

## Qué cambió

- Columnas `Nombre / Categoría / Ubicación / Estado` → `Pieza / Categoría / Ubicación / Disponibilidad / Relación / Alertas`.
- **Pieza:** nombre + id. Subtítulo solo si es `Producto por cantidad` o `Ensamblaje` (no se pinta “Pieza” en el caso normal).
- **Disponibilidad:** chip comercial existente (`Disponible` con peso bajo; `Vendido` / `No disponible` como excepción). En productos por cantidad, el stock (`N disponibles / M en existencia`) queda como subtítulo de esa misma celda (INV-004), no como estado fusionado.
- **Relación:** `Instalado en {padre}` (SEARCH-002), `Independiente` en texto atenuado, o `Producto por cantidad`.
- **Alertas:** solo excepciones (`Reservado`, `No desarmar`, `Incompleto`). No se duplica la disponibilidad.
- Ubicación vacía: `Sin ubicación registrada` (glosario), nunca “Pendiente”, con peso ámbar en el listado. El mismo fallback en detalle / edición.
- El test de ranking en `InventoryPage` dejó de buscar las etiquetas de clúster `Comercial` / `Físico` (UX-4) y ahora comprueba las columnas nuevas.
