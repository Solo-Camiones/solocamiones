## Objetivo

El administrador responde en segundos qué conviene atender, qué ocurrió hoy y cómo están las finanzas. Cada indicador relevante abre el listado ya existente, con el filtro en la query.

## Qué se entregó

### Inicio en tres grupos

- **Necesita atención:** componentes por validar, desmontes pendientes, tasas de cambio pendientes, ensamblajes incompletos. Tono ámbar si el conteo es mayor que cero.
- **Operación de hoy:** facturas de hoy, inventario disponible, órdenes en proceso (admin), borradores (vendedor, cuando la ganancia no se muestra).
- **Finanzas:** saldo pendiente, ganancia bruta (admin), cobros.

Se mantiene el banner de revisión de catálogo.

### KPIs como enlaces

`KpiCard` acepta `to` opcional (react-router `Link`, teclado, flecha discreta). Sin `to` sigue siendo una tarjeta estática (Rentabilidad, recuperación).

Los `href` salen de `OPERATIONAL_HREFS`. Destinos:

| KPI                        | Destino                                        |
| -------------------------- | ---------------------------------------------- |
| Componentes por validar    | `/inventory?pendingCatalog=1`                  |
| Desmontes pendientes       | `/work-orders?type=DISMANTLING&status=PENDING` |
| Tasas de cambio pendientes | `/profitability?pendingFx=1`                   |
| Ensamblajes incompletos    | `/inventory?assemblies=1&incomplete=1`         |
| Facturas de hoy            | `/sales?today=1`                               |
| Inventario disponible      | `/inventory?available=1`                       |
| Órdenes en proceso         | `/work-orders?status=IN_PROGRESS`              |
| Borradores                 | `/sales?tab=DRAFT`                             |
| Saldo pendiente            | `/sales?outstanding=1`                         |
| Ganancia bruta             | `/profitability`                               |
| Cobros                     | `/sales?payments=1`                            |

Los filtros de inventario los aplica otro entregable; aquí solo se enlaza.

### Destinos que honran la query

- **Ventas:** `tab`, `today=1` (día demo `2026-08-25`, misma regla de calendario que el KPI), `outstanding=1` (completadas con saldo > 0), `payments=1` (PAID o PARTIALLY_PAID). Chip para quitar el filtro.
- **Órdenes:** `status` mapea al TabBar; `type` filtra filas en cliente. Chip de tipo.
- **Rentabilidad:** `pendingFx=1` deja solo filas con tasa pendiente. Chip opcional.

### Roles y capabilities

Sin `PolicyAction` nuevos. Se reutilizan `can()` (`profit.view`, `workOrders.manage`, `inventory.admin`) y las omisiones ya proyectadas en el snapshot.

El vendedor no ve OT / desmonte, ganancia, ni componentes por validar. Sí puede ver saldo y cobros si `payments` está activo, y borradores en lugar de ganancia.

## Cómo verificar

- Administrador: tres encabezados de sección; KPIs de atención son enlaces con los `href` de la tabla.
- Vendedor: no aparecen Desmonte / OT / ganancia / componentes por validar; sí Borradores.
- `/work-orders?type=DISMANTLING&status=PENDING` muestra OD-DEMO-061 y oculta instalación pendiente.
- `/sales?outstanding=1` oculta facturas con saldo 0 (FAC-000096 / FAC-000097).
