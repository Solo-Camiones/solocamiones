**Estado:** Aprobado para construir ambientes (deployment plan M0 y M1 cerrados)

**Autoridad de despliegue:** `docs/deployment_plan/deployment_plan.md`

---

## 2. Excluido de `v2.0.0`

No implementar ni exponer como disponible en staging/producción de este release:

- Inventario ITEM / QTY, categorías de inventario, reservas (Releases 4–5)
- Jerarquía / baseline (Release 6)
- Work Orders / desarme / evidencia BEFORE-AFTER (Release 7)
- Cuentas por pagar / CxP (`FEATURES/15_*` — no confirmado)
- Correcciones protegidas / recovery completo (Release 8 restante)
- Importación de facturas físicas o saldos de apertura
- HA multi-VPS, failover multi-región, deploy productivo sin aprobación manual
- Base administrada externa, Kubernetes/Swarm/Nomad, acceso público directo al origen

Detalle operativo adicional: `docs/deployment_plan/deployment_plan.md` §21.

## 3. Flujos habilitados (smoke / go-live)

Como mínimo deben permanecer operativos tras el empaquetado:

- Autenticación y matriz negativa de roles
- Clientes y `Cliente contado`
- Catálogo de servicios
- Cotizaciones, conduces y facturas (DOP/USD, ITBIS, numeración `COT-` / `CON-` / `FAC-`)
- PDFs y regeneración
- Pagos, CxC, cancelación y reembolso (0…neto)
- Rentabilidad / FX
- Assistant documental + tools read-only (Admin), con kill switch / purge previstos en infraestructura

Lista operativa ampliada: deployment plan §16.

1. Fecha y SHA de commit de cierre
